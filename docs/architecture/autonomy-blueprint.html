The brain is code. The LLMs are hired hands.

How Hidayah runs a Tamil–Arabic–English Qur'an channel on YouTube and Instagram with nine specialised agents. Gemini does the language work, but every decision, rule, memory and gate lives in our own typed code and data. There are no free-form instruction files steering it.

1 · The principle

What "our brain" means in practice

An LLM agent driven by a markdown prompt decides for itself what to do, what is true and when it is done. Hidayah inverts that: the brain decides what happens and whether it is allowed; the LLM only produces a bounded piece of language that the brain then validates.

ConcernPlain prompt-file agentsHidayah (brain is ours)
InstructionsLong .md file the model reads and interpretsAgentSpec objects in TypeScript: role, input and output schemas, tools, policies, model and budget. Prompts are compiled from typed state at run time, versioned, and tested with evals.
DecisionsModel chooses the next stepA state machine chooses. Each transition has a guard written in code (for example, verification VERIFIED and budget reserved).
TruthModel memory and web snippetsSource registry: Qur'an text from two independent editions compared byte-for-byte; the model is never a source.
OutputFree text, parsed hopefullyJSON Schema output (Gemini responseSchema), validated with Zod; invalid output means retry or fall back to a template.
MemoryChat historyFirestore collections: channel state, registry, asset library, decisions ledger, performance history.
Learning"Write better next time"Analytics feed a scoring model (bandit over topic × look × slot) whose weights the Strategist reads. The numbers change, not the prose.
Safety"Please don't…" in the promptPolicy engine with tests: private-only uploads, licence checks, no scripture from models, spend caps, kill switch. An LLM cannot reach a tool that breaks a policy.
2 · The brain

Five parts we own

Policy engine

Rules as code with unit tests: religious-accuracy gates, licence and attribution, platform rules (private-first, AI disclosure), budget and rate limits, autonomy level. partial

State & memory

Firestore: verses, assets, jobs, decisions, posts, metrics. Every agent reads and writes typed records, never chat history. JSON files today

Contracts

Zod and JSON Schema for every agent's input and output, plus a Decision record (who, what, evidence, model, cost) for each step. partial

Orchestrator

A durable state machine (Cloud Workflows outside, an ADK graph inside). It handles retries, timeouts, idempotency keys, human-review holds and the kill switch. local today

Learning loop

YouTube Analytics and Instagram Insights → features → Thompson-sampling weights for topic, look, hook style and posting slot. Guarded so it can never pick an unapproved verse. to build

// An agent is data + code, not a prompt file
export const ScriptAgent: AgentSpec<ScriptIn, ScriptOut> = {
  id: "script", model: "gemini-3.8-flash", maxCostUsd: 0.01, timeoutMs: 60_000,
  input: ScriptIn,                       // Zod: verse ref, topic, translation (from registry), past hooks
  output: ScriptOut,                     // Zod: { hookTa ≤40 chars, hookEn ≤40 chars, style: enum }
  prompt: (s) => compile(hookTemplate, { topic: s.topic, meaning: s.translation.en, avoid: s.recentHooks }),
  policies: [noScriptureInEditorial, noQuotes, lengthLimit, notRepeatedLast30],
  fallback: (s) => templateHook(s.topic),  // used when output fails a policy or the model is down
  evals: "evals/script.golden.json",       // must pass in CI before a prompt change ships
};

Where the footage comes from

Adobe Stock clips licensed through your Express Premium account (9 plates, 8 moods so far), plus Firefly images you generate. They're stored in a footage library on Cloud Storage with mood tags and a grade preset each.

How the text stays exact

Arabic is split only at the verse's own waqf marks; translations only at matching sentence breaks; otherwise the whole verse is shown. Every on-screen line is re-checked against its source after the build.

What one Short costs

Footage is free-tier Stock (already licensed). Each Short makes about three short Gemini calls, costing well under one cent. Rendering takes about 15 minutes of CPU, which on a Cloud Run Job is a few cents.

5 · Distribution

YouTube and Instagram from the same master

YouTube Shorts

  • Data API v3, Desktop OAuth client (project hidaya-one-youtube), refresh token stored in Secret Manager
  • Upload always private, then publishAt per slot (07:00 / 13:00 / 19:30 IST)
  • De-duplicated by ledger and a hidden tag; quota 100 uploads/day
  • Analytics API: retention, engaged views, subscribers gained

Instagram Reels

  • Instagram Graph API with an Instagram Professional (Business or Creator) account, through a Meta app with content-publish permission
  • Flow: create a REELS media container from a public video URL (a short-lived Cloud Storage signed URL), wait for FINISHED, then media_publish
  • Same 1080×1920 master; caption adapted per platform (hashtags, Tamil first line)
  • Insights API for plays, reach and saves feed the same learning loop

You'll need to provide for Instagram: the Instagram account switched to Professional, a Meta developer app, and approval of the publishing permission. Until that exists the Distributor produces Reels-ready files and captions only.
